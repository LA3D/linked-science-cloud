# Revision workflow

Run commands from the repository package root. Read `schemas/wiki-learning/pattern.schema.json` and `wiki-proposal.schema.json` for exact fields. The saved example is `artifacts/wiki-learning/proposals/ontology-membership-seed.json`; it is a historical proposal, not a replayable command against later revisions.

## Select or capture eligible evidence

Use the supplied scientific episode and existing saved records first. For a new episode, preserve only bounded, nonsensitive action/outcome observations and receipts already available in the authorized task under `artifacts/wiki-learning/`; create an explicit corpus descriptor under `artifacts/wiki-learning/corpus/`. Read [the episode schema](../../../../schemas/wiki-learning/episode.schema.json), [corpus schema](../../../../schemas/wiki-learning/corpus.schema.json), and [scientific corpus contract](../../../../docs/experiments/scientific-workflow-corpus.md) when capture is needed. The [saved episode](../../../../artifacts/wiki-learning/scientific/ontology-membership-20260919/episode.json) and [corpus descriptor](../../../../artifacts/wiki-learning/corpus/ontology-membership.json) show the supported structure, not IDs or evidence to reuse.

The current corpus adapter accepts `direct-runtime` episodes with actual `linked-science-observed-mcp-exchange/v1` project-stdio witnesses. Match normalized observations to raw exchanges, retain actual event and operation IDs, and hash saved bytes. Do not relabel other host formats, infer joins from timestamps, invent checks, or copy outcomes from an example. Scope classification is the acting maintainer's evidence-based judgment, not asserted human approval.

For deliberately supplied selected history, `node scripts/wiki-learning/import-episode.mjs <supplied-input.json> artifacts/wiki-learning/episodes/<unique-name>` accepts `pages`, `selections`, `draft` and `readOptions` (see [the importer](../../../../lib/wiki-learning/episode-import.mjs)). It retains metadata and bounded excerpts, not scientific output witnesses. Such an import is partial context and cannot by itself satisfy direct-runtime eligibility. Do not scan unrelated history or export source datasets to fill gaps.

Inspect a new explicit record with `inspectCorpusRecord(record, { root })` from [the corpus module](../../../../lib/wiki-learning/corpus.mjs); `root` is the absolute repository path. `node scripts/wiki-learning/validate-corpus.mjs` checks its fixed seed list, not arbitrary new records. Proposal `inspect` below validates every selected corpus citation, including new records. Only `observed-within-scope` units may support an applied pattern. If witnesses are missing or the live host format is unsupported, leave a concise task-handoff note with the candidate decision, available references and exact gap; keep any partial record incomplete and out of the wiki. Continue without acquiring extra evidence merely for learning.

## Revise the canonical pattern

Read the current bounded index and relevant patterns before writing. Prefer updating an existing decision over adding an entry. Keep actionable scope and uncertainty concise; leave detailed episode context behind citations. The pattern is the single authored lesson; generated pages/index are views, not a second procedure library. Evidence-backed proposed lessons need no performance test to be saved or consulted. Validation of candidate active-skill changes remains separate.

1. Read `wiki/HEAD`, validate the current revision and select explicit hashed corpus descriptors. Record the batch purpose, maximum unique units, observed outcome strata and omitted material. Proposals carry the exact base revision; null means an empty wiki.
2. Write a bounded JSON proposal under `artifacts/wiki-learning/proposals/`. Each citation names a whole hashed corpus record, a unit, its witness event IDs, source/receipt evidence IDs and verified operation IDs. Include all witnesses and joined receipts. The helper reuses the scientific corpus and episode validators; missing or changed evidence fails closed.
3. Inspect with `node scripts/wiki-learning/wiki.mjs inspect <proposal-path>`. Proposed changes remain data. For an in-scope agent-initiated lesson, standing project learning authority covers inspection and local application without additional confirmation. Apply with: `node scripts/wiki-learning/wiki.mjs apply <proposal-path>`.
4. To review/promote or change already reviewed content, supply `--review-file <path>` naming a JSON object with `reviewer` and `authorization` strings. This records the caller's asserted authorization; it does not authenticate a human or grant permission. For a correction or contradiction covered by project learning authority, identify the acting agent as reviewer and cite that authority and task context; never label it human review. Promotion to reviewed status needs authority for that concrete promotion. Use an accurate reviewer identity and actual authorization. Reviewing a candidate does not establish generality.
5. Validate after application. The CLI prints the committed revision. Pages, the deterministic bounded index, exact proposal and evolution history live together under `wiki/revisions/<revision>/`. `wiki/HEAD` changes atomically only after that snapshot is complete. Git commit remains the repository delivery step.

Relations name pattern IDs. A `supersedes` target must have status `superseded`, and a `contradicts` target must have status `contradicted` in the same resulting snapshot. Supply both changes atomically. Inactive pages never enter reviewed/current index sections. No pattern deletions are supported; use `withdrawn` with authorized review.

A stale base revision or held writer lock is a conflict, not permission to overwrite. Read the new state and reconsider the proposal. Never auto-steal a lock: confirm an interrupted writer is gone before authorized manual cleanup. Interrupted pre-commit snapshots are ignored by HEAD and can be inspected; preserve the old committed revision. This provides process-interruption recovery for cooperative local writers, not distributed locking, tamper-proof authorship or a power-loss guarantee. Corrupt or missing evidence blocks validated reading/application until evidence is repaired or the limitation is handled explicitly; do not bypass the validator to promote stale guidance.

Bounds: at most 16 changed patterns, 16 selected corpus records, 64 unique selected units, 256 stored patterns/revisions, 64 KiB index and 2 MiB snapshot metadata. Reaching a bound is an explicit error; do not silently truncate or increase it during a run.

The initial seed has proposed recovery guidance and a separate dated GO-overlap finding. It has no independent counterexample or transfer evidence. A reviewed hypothesis with an observed counterexample remains an unmet evaluation milestone, not a requirement to fabricate one.
