## Current map and proposed enrichment

`updateOrientationForHandle` in the [runtime](../../lib/linked-science-runtime.mjs) skips query results and records identity/version, role/type, optional media type, and ephemeral handle/epoch. It assigns ontology/schema/SHACL references to `parsing-schema`, others to `context-roadmap`. An explicit `orientationContext` shares orientation while inventories remain separate. Source identity and version fields are useful, but do not automatically encode semantic dependencies.

The [PEEK broker scaffold](../../packages/cleanroom-node-repl/src/peek-runtime.mjs) provides five sections, stable IDs, ADD/DELETE/REPLACE and estimated-token eviction. Scores default to 0.5 (runtime references use 0.8/0.7); an optional policy is unconfigured by default. Explicit map retrieval is not automatic prompt presence. Handle invalidation is not semantic freshness validation.

[PEEK sections 3.1–3.2](https://arxiv.org/html/2605.19932v1#S3) distinguish source roadmap from entities/concepts/relationships, separate extraction from local edits, and present a bounded map on each run. The paper learns maintenance from trajectories; this proposed agent-generated comparison is an ablation inspired by that design, not a replication. Its benchmark gains do not transfer as evidence here.

### Smallest automatic implementation slice (proposed, not implemented)

Keep `linkedScience.open()` synchronous and preserve its workspace return value. Reuse the existing orientation owner, context key, broker `PeekRegistry`, local fallback map and storage ceilings. Do not add a provider, learned Distiller, new datastore, background worker, or implicit acquisition. Current `commit()` sends only a checkpoint event to the optional policy; it is not the proposed semantic update path.

1. **Automatic source bookkeeping.** Extend `updateOrientationForHandle` to attach a runtime-owned source key, representation fingerprint, evidence reference and provenance scope. Preserve metadata creation without semantic proposals. Do not promote query results into the source catalog automatically; a proposal may cite a result and the runtime resolves its recorded lineage. Keep original-source identity separate from the identity/hash of a reconstructed artifact. Record unknown upstream versions as unknown rather than treating a fixture hash as a live release. Source metadata remains descriptive and conveys no new authority.
2. **One structured operation.** Add proposed `await ws.orientation.update({ edits })`, with ADD/REPLACE/DELETE actions, stable entry IDs and a bounded batch. ADD/REPLACE carry `{ text, section, claimKind, evidence }`; `claimKind` distinguishes an observed relationship, a documented meaning, and an interpretation. Evidence consists of typed resident handle references plus bounded selectors (exact RDF term/triple, row range, or text span). Agent-supplied source/version assertions are not trusted: the runtime attaches dependencies from resolved records and lineage. Use `context-understanding` for meanings and relationships; reserve `parsing-schema` for format structure. No prewritten UniProt entries, query templates, or source-specific update branches.
3. **Deterministic validation.** Validate shape, size, supported section/claim kind, edit ownership, handle epoch and workspace authority, selector existence, and complete recorded lineage closure within the current orientation context. An arbitrary URL or an old handle ID is insufficient evidence. Reject unresolved lineage rather than marking it verified; the agent can cite currently resident primary evidence instead. Validate replacement targets before editing and forbid semantic edits to runtime-owned source records. Validation proves that the cited observation exists and dependencies were recorded; it does not prove that the prose follows from the observation, that the agent cited everything relevant, or that a claim is universally true. Store `validation: references-checked` and `semanticStatus: agent-proposed`, never an automatic truth endorsement.
4. **Bounded local application.** Encode validated semantic records in the existing entry text envelope and use existing editing/eviction. Add only the adapter needed for equivalent local fallback behavior. Bound each proposal by existing 8 KiB entry/64-edit maxima and a tighter facade batch byte cap within runtime output limits. Prevalidate the whole batch before mutation: current `PeekRegistry.edit` can mutate earlier edits before a later edit fails, so atomic validation/application is a concrete small change, not assumed behavior. Recheck evidence epoch and source fingerprints at application time; serialize update/source-change edits per orientation context so a concurrent reset or version change cannot publish a falsely current entry. Return a bounded receipt with accepted/rejected IDs, reason codes, evicted IDs/count and current map status. Fixed scores remain adequate; agents do not gain arbitrary priority control.
5. **Dependency change flags.** On observing another fingerprint for the same source key within an orientation context, flag dependent semantic entries `dependency-changed` and record old/new fingerprints. For the first slice scan the already bounded entries rather than create a reverse-index service. Cross-source claims include all recorded dependencies. A flag means revalidation is required, not that the claim is false. Valid replacement using new observations clears the flag; absence of a fresh observation cannot clear it. An explicit new `orientationContext.version` creates a different map, not an automatic migration.
6. **Real presentation boundary.** Extend proposed `await ws.orientation.bootstrap({ maxBytes, ... })` to initialize-or-resume and return a bounded `{ status, entries, omittedCount, dependencyFlags, residency }` presentation. The generic REPL entry sequence is `var ws = linkedScience.open(...); nodeRepl.write(await ws.orientation.bootstrap({ maxBytes: 4096 }));` on opening or resuming a question context. This is tool-result delivery at an explicit call; neither `open()` nor storing a map places it in the host prompt. Update the generic startup/resume guidance and test that sequence. No host system-prompt injection is promised. Repeated calls are idempotent; omitted entries stay stored. Do not silently reset a resumed map's configured token budget as current bootstrap's default `maxItems` could do. Keep strict `current()` for explicit inspection; bounded bootstrap should return a fitting subset/status instead of failing when the complete map exceeds presentation bytes.

The semantic record holds compact evidence locators and dependencies, not whole payloads. Maps may outlive kernel handles where the existing broker permits, but do not restore data, grant access, or establish current source availability. Shared orientation does not authorize reads of another workspace's registry. Revalidation requires newly accessible evidence. If source metadata is evicted, retained semantic dependencies still preserve their last observed fingerprint and must report `source-not-observed` on a fresh/resumed workspace until checked; they cannot silently claim current freshness.

### Failure and fallback contract

| Situation | Proposed bounded status and behavior |
| --- | --- |
| First open / missing map | `empty`, zero entries; initialize through existing owner and continue ordinary exploration. No assumed checkpoint or hidden bindings. |
| Source bookkeeping failure / broker map unavailable | `unavailable` or `update-failed` with bounded reason; retain successful source/data operation and its provenance. Avoid hiding a successfully acquired handle behind an optional orientation failure. No hidden retry or second owner pretending continuity. |
| Invalid proposal | `rejected`, structured repair reasons, no partial edit; source/query handles remain usable. Agent may repair within normal budgets or continue without enrichment. |
| No proposal during exploration | Metadata-only map remains valid; semantic count zero is visible. Normal query execution never waits for a semantic entry. |
| Changed dependency | Display flagged entry as historical/unverified, not current guidance; agent may reobserve, replace/delete, or proceed directly from source evidence. |
| Handle release/reset | Separately show evidence residency unavailable/stale; keep historical semantic scope when the owner retains it. Never label epoch loss a source-version change. Whole broker/map loss returns to `empty`. |
| Eviction / presentation truncation | Report counts/IDs boundedly and distinguish eviction from omission. Do not create hidden unlimited dependency storage; rediscovery is an allowed fallback. |
